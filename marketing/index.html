OutThe file tree, A to Z.

InEach file tagged by where it sits: L-1 what the change relies on, L0 the change, L1 what it affects. Tests and generated files stay hidden until you ask.

OutEvery diff, stacked top to bottom.

InBobby's Diff view: the same diffs and threads, one file at a time, each placed right of the files it relies on.

One change. One question.

OutThe whole diff at once.

InThe Lens view splits the PR into cores, one idea each, and opens each with a question to keep in mind. With Claude Code installed, Claude names the cores and writes the questions.

05 · Context

What it relies on. What it affects.

OutSearching the repo for who calls it.

InThe code around the change, and how each piece connects, including code the PR never touched. That's where bugs hide.

06 · Comments

InEvery GitHub thread under its line. Your comments wait as drafts; private notes never leave your machine.

07 · Progress

Walk it, mark it, move on.

Out"Viewed" checkboxes, file by file.

Inj k walk the PR in order; a marks a page looked at and moves on. Marks follow the code, so after a force-push only what changed comes back.

08 · Interruptions

Park the thought.

OutLosing your place to a ping.

Inp parks what's in your head before you switch away. It waits for you in the bar.

09 · Coming back

Pick up where you left off.

OutScrolling around for where you were.

InWhere you were, how far you got, and the thought you parked. Progress survives restarts and force-pushes.

10 · Submit

One review, one key.

Out"Review changes", at the end of a long page.

Ins posts every draft as one GitHub review: comment, approve or request changes. Private notes stay on your machine.

InThe Conversation view is GitHub's own timeline, read live: your review is already in it, next to everyone else's.
